Beyond Accuracy Claims: A Casemix-by-Casemix Blueprint for Autonomous Clinical Coding.

Autonomy Without Evidence Is Risk. Autonomy With Proof Is Transformation.

How HCS v2.0 moves from coder assistance to measured, governed and provable automation.

Core Message

Measured. Tuned. Governed. Proven.

On your own hospital's casemix before autonomy is enabled.

MeasuredPerformance is quantified at the coding decisions that matter.
TunedModels and rules are refined against actual coding outcomes.
GovernedAutonomy remains controlled, visible and auditable.
ProvenAutomation is enabled only after validation on customer episodes.
01 — Measured

Accuracy is defined at every coding decision.

Rather than relying on a single headline accuracy number, the HCS v2.0 narrative measures performance across the coding decisions that drive the final episode outcome and benchmarks performance against the hospital's own coding standard.

Question answered: At what level is accuracy measured?

What the validation should show

  • Separate measurement across principal diagnosis, additional diagnoses, procedure coding and final DRG outcome.
  • Benchmarking against the customer's own coded episodes.
  • Clear boundaries around documentation quality, document scope and grouping logic.
  • Performance evidence before any move toward autonomy.
02 — Tuned

Refined against real coding outcomes.

The operating model should make coder correction part of the learning loop. HIM teams retain ownership of the benchmark, rule library and release decision, while corrections are classified at the relevant coding segment rather than disappearing into a generic model update.

Question answered: What happens to a coder's correction?

What tuning should make visible

  • Decision-specific logic and specialist coding behaviour.
  • Coder corrections classified by coding segment and cause.
  • Rules and coding guidance maintained with accountable ownership.
  • A repeatable feedback loop between validation, correction and controlled release.
03 — Governed

Controlled and auditable before billing.

Governance is not an afterthought. The HCS v2.0 narrative places controls between AI output and the confirmed billing outcome, giving coders and HIM leaders visibility into evidence, exceptions and release decisions.

Question answered: What control sits between the confirmed DRG and the claim?

Governance points

  • Coding validation.
  • Grouping validation.
  • DRG confirmation.
  • Retrospective audit and governance review.
  • Reasoning/evidence visible to the user at validation.
  • Pre-bill controls for episodes requiring review.
04 — Proven

Autonomy is earned, not assumed.

The HCS v2.0 story moves along a maturity curve only after performance is demonstrated first in benchmark validation and then at production scale. That keeps autonomy tied to evidence rather than marketing claims.

Questions answered: Against whose coding is it benchmarked? Will you show the failures?

Two gates before autonomy

  • Gate 1 — benchmarked performance on the hospital's own casemix.
  • Gate 2 — proof that performance remains stable at production scale.
  • Exceptions and failure modes remain visible to governance teams.
  • Autonomy expands only where evidence supports it.
Autonomy Maturity Curve

Move from assistance to straight-through only where evidence supports it.

Stage 1Coder-Assisted

AI supports the coder while human review remains the primary control.

Stage 2Validated Assistance

Performance is measured and tuned against real coded episodes.

Stage 3Selective Autonomy

Defined casemix areas can move forward under explicit governance gates.

Stage 4Straight-Through

Automation is enabled only where performance has been proven and remains governed.

Transformation

Redirect coder capacity to the work that needs expert judgement most.

The end-state is not simply fewer touches. It is a different operating model: repeatable casemix can move through validated automation while coder capacity shifts toward complex DRGs, exceptions, audit and higher-value review.
